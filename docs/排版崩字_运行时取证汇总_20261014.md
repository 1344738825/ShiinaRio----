> **`0x43aa xx` / `0x43b4 xx` 那一整片排版代码（含换行判定 `0x43aac6`、`0x43b498`）在运行时从未执行。**

## 1. 决定性实测数据（frida 运行时读取）

### 1.1 排版结构体字段实际值 ★★★

来源：hook `0x416f42`（`call 0x43a2a0` 之前），读 `edi` 结构体。

```
LOOP #1  edi=0x505e34  ebx=0x914ce8  idx=1  esp+14=9522408
         [edi+0x19c]=640   [edi+0x178]=8   [edi+0x180]=16   [edi+0x184]=0
```

| 偏移 | 实测值 | 语义（本轮确认） |
|---|---|---|
| `[edi+0x160]` | （读取失败，需重测）| 当前字符指针 |
| `[edi+0x178]` | **8** | 空格格数 / 宽度模式（`-1` = 特殊模式）|
| `[edi+0x180]` | **16** | 双字节附加宽 |
| `[edi+0x184]` | **0** | 单步宽（**无默认初始化 → 0**）|
| `[edi+0x19c]` | **640** | **行宽阈值**（★ 推翻此前"512"的记录）|
| `[edi+0x1620]` | 运行时 = ebx | 父/全局上下文（`0x416f29` 写入）|

**推导**：双字节每字宽 = `[0x180] + 2×[0x184]` = `16 + 0` = **16px**
**→ 640 ÷ 16 = 40 字/行**（与实测"28 字就换行"**矛盾**，见 §5）

### 1.2 结构体地址公式

`edi = 0x5047c8 + idx × 0x2f4` 形式（`0x416f10`–`0x416f21` 计算），实测量 `edi = 0x505e34`（idx=1）。

### 1.3 初始化函数写死的默认值（`0x43b76f`–`0x43b79d`）

```asm
0043b76f: mov dword ptr [esi + 0x178], 8       ; 空格格数
0043b779: mov dword ptr [esi + 0x180], 0x10    ; 双字节附加宽 = 16
0043b783: mov dword ptr [esi + 0x17c], 0x10    ; 行高 = 16
0043b78d: mov dword ptr [esi + 0x188], ecx
0043b793: mov dword ptr [esi + 0x19c], 0x280   ; ★ 行宽 = 640
0043b79d: mov dword ptr [esi + 0x1a4], ecx
```

**注意：该初始化函数从未写 `[esi+0x184]` → 保持 0。**

### 1.4 `[esi+0x184]` 的唯一写入点是文本内联控制码

```asm
004388a0: cmp byte [eax], 0x5a      ; 'Z'
004388a5: inc eax
004388a7: [esi+0x160] = eax
004388ad: call 0x4384b0             ; 读数值参数
004388b6: [esi+0x180] = eax         ; 'Z<num>' → 双字节附加宽
...
004388c5: call 0x4384b0
004388cb: [esi+0x178] = eax
004388d1: add eax, eax
004388d3: [esi+0x180] = eax         ; 0x180 = 0x178 × 2
004388df: al = byte [ecx-1]
004388e5: cmp al, 0x2c              ; ','
004388ed: call 0x4384b0
004388f7: [esi+0x184] = eax         ; ',<num>' → 单步宽
```

**→ KYO1.TXT 的台词文本里可以内嵌 `Z<num>` / `<n>,<n>` 排版控制码。**
**实测：L2 台词行内无任何 ASCII 控制码 → 走默认参数（`[0x184]=0`）。**

## 2. 真正的逐字绘制循环 `0x416f10`（★ 本轮最大发现）

```asm
00416f10: mov ecx, [ebx+0x1004]         ; 文本块索引
00416f16: lea eax, [ecx + ecx*8]
00416f19: shl eax, 5
00416f1c: sub eax, ecx
00416f1e: lea edx, [eax + eax*4]
00416f21: lea edi, [edx*4 + 0x5047c8]   ; ★ 计算排版结构体地址
00416f28: push edi
00416f29: mov [edi+0x1620], ebx         ; ★ 回填父上下文
00416f2f: call 0x4384a0                 ; 取下一个字符数据
00416f34: add esp, 4
00416f37: test eax, eax
00416f39: je 0x416f54                   ; 取完 → 退出
00416f3b: mov eax, [esp+0x14]
00416f3f: push ebp                      ; 0
00416f40: push eax
00416f41: push edi
00416f42: call 0x43a2a0                 ; ★ 逐字绘制
00416f47: push edi                      ; ← 返回地址（caller 名 0x416f47）
00416f48: call 0x4384a0
00416f4d: add esp, 0x10
00416f50: test eax, eax
00416f52: jne 0x416f3b                  ; ★ 循环
00416f54: ...
```

**调用者实测**：`caller=CHOSAIMIN.EXE+0x16f47`（即 `0x416f47`）。

### 2.1 该循环的两大未解点

1. **`0x43a2a0` 每次返回 `ret=0x0`（失败）**，且内部 `esi = 0xffffffff`（读第二个参数时为无效值）。
   - 实测 `0x43a2a0` 的 `onLeave ret=0x0`（连续 177 次）
   - → 该函数**提前失败返回**，未走到内部的 `TextOutA`（`0x43a285`）
2. **`0x43a2a0` 在启动 16 秒内被调用 177 次**，之后不再调用（疑为初始化/字模预生成路径）

## 5. 当前核心矛盾（未解）

> **静态/实测宽度账**：每字宽 16px，行宽 640 → **40 字/行**
> **实测现象**：L2 仅 **28 字**就换行/崩字（B 测试：29 字反而不崩）

**推论**：生效的排版循环**不是** `0x43aa xx`/`0x43b4 xx`（那片的宽度累加 `[0x180]+[0x184]×n` 逻辑），
而是 **`0x416f10` 循环 + `0x4384a0`（取字符）** 内部另有宽度计算。

**★ 下一步最高价值目标：反汇编 `0x4384a0`（取字符函数）**
—— 它决定：① 如何切分 GBK 字节；② 每个字符推进多宽；③ 何时触发换行。

## 0. 一句话定案

> **排版宽度累加 + 换行判定的真正位置已静态钉死：RVA `0x3a99f`–`0x3aac6`**，
> 它**位于 `0x3a2a0` 函数体内**；而 `0x3a2a0` 的调用者实测包含 **`call @RVA 0x16f42`（VA 0x416f42）**，
> 与 §19.4 frida 实测的返回地址 `CHOSAIMIN.EXE+0x16f47` **完全吻合**。
> **⇒ §19「`0x43aa xx` / `0x43b4 xx` 那整片排版代码运行时从未执行」的结论不成立。**

## 1. 两个地址记账错误（必须更正，否则静态分析全错）

### 1.1 VA / RVA 混用

`CHOSAIMIN.EXE`（md5 `a70efcc539882fa057210d2e94c26834`，1179648 字节）：

| 节 | VA | VSize | RawPtr | RawSize |
|---|---|---|---|---|
| .text | 0x001000 | 0x09f825 | 0x001000 | 0x0a0000 |
| .rdata | 0x0a1000 | 0x018544 | 0x0a1000 | 0x019000 |
| .data | 0x0ba000 | 0xa1346c | 0x0ba000 | 0x030000 |

- ImageBase = `0x400000`
- `.text` 只覆盖 RVA `0x1000`–`0xa0825`
- **文档 §19 里的 `0x416f10` / `0x43a2a0` / `0x43aac6` / `0x43b498` / `0x43b76f` 全部是 VA（frida 下正确），对应 RVA 必须 −0x400000**

| 文档写的 | 实际含义 | 正确 RVA |
|---|---|---|
| `0x416f10` | VA | `0x16f10` |
| `0x4384a0` | VA | `0x384a0` |
| `0x43a2a0` | VA | `0x3a2a0` |
| `0x43aac6` | VA | `0x3aac6` |
| `0x43b498` | VA | `0x3b498` |
| `0x43b76f` | VA | `0x3b76f` |
| `0x5047c8`（结构体基址）| VA | `0x1047c8` |

> 直接用 0x4384a0 等做**文件偏移**去 read() 会得到空切片（4.4MB > 1.18MB 文件）。
> 这是本轮开始时踩到的第一个坑。

### 1.2 结构体步长错误

文档 §19.5 写「`edi = 0x5047c8 + idx × 0x2f4`」—— **错**。

`0x416f16`–`0x416f21` 实际计算：
```
lea eax, [ecx + ecx*8]    ; ecx*9
shl eax, 5                ; ecx*288
sub eax, ecx              ; ecx*287
lea edx, [eax + eax*4]    ; ecx*1435
lea edi, [edx*4 + 0x5047c8]; 0x5047c8 + ecx*5740
```

**步长 = 5740 = `0x166C`**（不是 0x2f4）。
验算：idx=1 → `0x5047c8 + 5740 = 0x505E34` ✓（与 §19.5 实测 `edi=0x505e34` 吻合）。
用文档的 0x2f4 算 idx=1 得 0x504abc，**与实测不符**。

## 2. `0x416f10` 循环的真实语义（§19.4 更正）

```asm
016f10: ecx = [ebx+0x1004]           ; 文本块索引 idx
016f16-21: edi = 0x5047c8 + idx*5740 ; 结构体指针
016f29: [edi+0x1620] = ebx
016f2f: call 0x384a0                 ; = return *(uint32_t*)(arg+8)   ← 3 条指令
016f37: test eax,eax / je 退出
016f3b: eax = [esp+0x14]
016f42: call 0x3a2a0(edi, ebp, eax)  ; ★ 处理一个块（内层：逐字符排版/绘制）
016f48: call 0x384a0
016f52: jne 0x16f3b                  ; 循环
```

- **`0x4384a0`（VA）= RVA `0x384a0` 只有 3 条指令**：`mov eax,[esp+4]; mov eax,[eax+8]; ret`
  —— 它是**读结构体 `[+8]` 标志字段**的 getter，**不是"取下一个字符数据"**（§19.6 命名有误）。
  该字段由 `0x3a2a0` 内部 `mov dword ptr [esi+8], 2`（RVA `0x3a2b6`）写入，
  所以 §19.6「`0x43a2a0` 每次 ret=0 提前失败」是**观察错位**：getter 读的是 `[+8]`，值为 2（非零）。
- **真正的"取字符"在 `0x3a2a0` 函数体内**（RVA 0x3a99f 段）。

**已闭环证据（caller 扫描）**：`0x3a2a0` 的调用者 = `0x16f42` / `0x17022` / `0x17090` / `0x32834` / `0x3b676`，
其中 `0x16f42` 与 §19.4 实测返回地址 `CHOSAIMIN.EXE+0x16f47`（= 0x16f42+5）一致。

## 3. ★ 真正的排版宽度累加 + 换行判定（RVA 0x3a99f–0x3aac6）

```asm
; ---- 取当前字符、判定字节数（= 第 2 个解码器副本，已 patch 0x9F→0xFE）----
03a99f: eax = [esi+0x160]              ; 当前字符指针
03a9a5: cl = [eax]
03a9a7: cmp cl, 0x81 ; jb  单字节
03a9ac: cmp cl, 0xfe ; jbe 双字节      ; ★ 已 patch（原 0x9f）
03a9b1: cmp cl, 0xe0 ; jb  单字节
03a9b6: cmp cl, 0xfc ; ja  单字节
03a9bb: ecx = 1                        ; 双字节标志
03a9c4: edi = eax + ecx + 1            ; 下一字符指针
03a9c8: ecx = edi - eax                ; ★ 本字符字节数 = 1 或 2
03a9db: (1字节) [esi+0x610] = byte[eax]
03a9e5: (2字节) [esi+0x610] = word[eax]   ; ★ 双字节原样送下游
...
03aa5a: [esi+0x160] = edi              ; 推进指针

; ---- 宽度累加 ----
03aa60: eax = [esi+0x178]              ; 空格格数
03aa66: cmp eax, -1
03aab3: (双字节) eax = [esi+0x180]     ; = 16 双字节附加宽
03aab9: edx = [esi+0x184]              ; = 单步宽
03aabf: edx *= ecx                     ; edx = 单步宽 × 字节数(1/2)
03aac2: edi += eax
03aac4: edi += edx                     ; ★ 累加宽度

; ---- 换行判定 ----
03aac6: cmp edi, [esi+0x19c]           ; ★ 当前宽度 vs 行宽阈值(640)
03aacc: jb  0x3ab44                    ; 未超 → 继续
03aace-...: (超过) 匹配排除表 → 执行换行
03ab14: [esi+0x16c] += [esi+0x17c]     ; y += 行高(16)
```

**宽度公式（确认）**：
- 双字节字符：`宽度 += [0x180] + 2×[0x184]` = `16 + 2×[0x184]`
- 单字节字符：`宽度 += 0 + 1×[0x184]` = `[0x184]`

**若 `[0x184] = 0`（§19.5 实测）→ 每汉字 16px → 640 ÷ 16 = 40 字/行。**

## 4. 排除表匹配（隐藏的"提前换行"机制）

`0x3aace`–`0x3b04f`：当宽度**超阈值**时，会去查两个**字符排除表**：

- `[esi+0x2b8]`：`lea eax,[esi+0x2b8]` 起，`add eax,2`，`cmp cx,bx`(0) 为终止，`cmp cx,dx`(当前字符 `[esi+0x610]`)
- `[esi+0x3b8]`：同上，`lea edx,[esi+0x3b8]`
- `[esi+0x1b8]`：同构，`lea ecx,[esi+0x1b8]`

**语义推测**：这些是「**禁则处理**」表 —— 行尾不允许出现的字符（如 `，。！？`、引号、括号等）。
超阈值时若当前字符在排除表里，**不换行**（把该标点留在行尾）或**强制提前换行**。
`[esi+0x1ac]` 被置 0/1，是"本行已有标点处理"之类的状态位。

**→ 这是"28 字就换行"的第一个候选解释**：L2 文本在第 28 字处宽度**已达 640**（即每字实际 >16px，或起点有偏移），
或者查表命中触发了特殊换行。

## 5. §19.8「静态账 40 字/行 vs 实测 28 字」的可能解释（待运行时验证）

| 假设 | 依据 | 验证方法 |
|---|---|---|
| H1 `[0x184]` ≠ 0 | §19.5 在 `0x416f42` 读 `edi`，但**该函数用的是 `esi`**；两者虽同址但读时机不同 | hook 0x3aab9 读 `[esi+0x184]` |
| H2 `[0x19c]` ≠ 640（被控制码改小） | 文本内联 `Z<num>` / `<n>` 可改 `[0x178]/[0x180]/[0x184]`；`0x4388a0` 解析器 | 检查 L2 行内是否含 ASCII 控制码 |
| H3 起点 x 非 0 | `[esi+0x168]` 初始值可能是缩进 | hook 0x416f42 读 `[esi+0x168]` |
| H4 排除表命中提前换行 | §4 的三张表 | hook 0x3aacc 看是否 jb 失败次数 |
| H5 宽度累加有第二处 | `0x3bc5b`/`0x3b45c` 也有 `[0x180]` 引用 | 需排查 |

**H2 快速判定（静态，无需跑游戏）**：读 KYO1.TXT L2 原始字节 —— §19.9 已给：
```
ce d2 b0 d1 ba a6 d0 df ... a1 a3 0d 0a 0d 0a
```
**全部是 GBK 双字节 + `。`(a1a3)，无任何 ASCII（<0x80）控制码** → **H2 排除**。

**H1 快速判定（静态）**：`[esi+0x184]` 的唯一写入点是文本控制码 `,<num>`（RVA `0x388f7`）。
全文本无控制码 → **`[0x184]` 恒为初始化值**。而初始化块 `0x3b76f` **只写 0x178/0x180/0x17c/0x19c/0x1a4**，
**从不写 0x184** → 该字段是**未初始化的内存残留值**，**不保证为 0**！

> ★ **这是最强候选：`[esi+0x184]`（单步宽）从未被本函数的初始化路径赋值，是堆/静态区残留值。**
> §19.5 实测到 0，但那可能是**那一次**的残留；若为 0 → 40 字/行（与 28 不符），
> 若为非 0（比如 6）→ 每字 16+12=28px → **640/28 ≈ 22.8**… 仍不精确等于 28 字。
>
> 若要 28 字/行：每字宽 = 640/28 ≈ 22.857 —— 非整数，说明**不是均匀字宽**，
> 更可能是 **H3 起点偏移** 或 **H4 排除表** 导致，或 `[0x19c]` 不是 640。

**下一轮必做的运行时取证（3 个 hook，低成本）**：
1. `0x3aab9`（RVA）读 `[esi+0x184]`、`[esi+0x180]`、`[esi+0x19c]`、`[esi+0x168]`、`[esi+0x160]`
2. `0x3aac6`（RVA）读 `edi`（累加宽度）与 `[esi+0x19c]`，打印每字符累进
3. 打印 L2 这一行**每次累加后的宽度序列** → 直接看出第几个字越过 640

> 注意：hook 必须用 **VA**（frida）：`0x43aab9` / `0x43aac6`，且**内部指令 hook 要挂对模块基址**。

**回填优先级**：`fill_cn.py` 是「后写覆盖先写」。重译/修正稿务必放在原稿之后传入参数。
一次性重放全部已写译文（按文件修改时间升序，安全幂等）：

```bash
python -c "
import glob, os, subprocess, sys
fs = sorted(glob.glob('work/cn_*.tsv'), key=os.path.getmtime)
subprocess.run([sys.executable, 'tools/fill_cn.py'] + fs)
"
```

## 三、翻译口径

**默认一律精翻，中性化只作兜底。** 详见 **`中性化处理登记.md`**（含术语对照表、角色语气约定、兜底触发条件、自检命令）。

要点复述：
- 不要因为内容露骨就主动软化 —— 那正是精翻对象
- 术语表已定案（セックス=做爱 等），**不要另起炉灶**
- 角色语气不要抹平：茉莉花=大小姐、佳澄=口齿不清（窝/的说）、杏子=咬字破碎
- 符号：`♪`→`☆`、`①` 保留、`【】` 保留、全角空格保留
- 编码 CP936/GBK

自检：
```bash
python tools/scan_soften.py          # 未登记却用了虚化措辞 = 返工项
```

## 六、已知陷阱（踩过的坑）

1. **tsv 必须 `utf-8-sig` 读取** — Write 工具产出的文件带 BOM，早期因此报 `FileNotFoundError`。
2. **不要导出 `kind=command/comment`** — 早期版本误导出命令行，回填时触发 `assert r['kind'] in ('text','name')`。
3. **人名标签是 `cn==jp` 的正常状态**，不要当成未译去「翻译」。纯人名行请走 `fill_names.py` 批量填，别逐条写 tsv。
4. **`fill_cn.py` 的 GBK 校验是严格的**（早期是 `errors='ignore'`，会静默放过不可编码字符，一路混到 apply 才炸）。
5. **回填前先跑 `fill_names.py`** — 人名占剩余量的大头（本轮一次砍掉 6333 行），先清掉再统计才准。
6. **`work/*_todo.tsv`（tab 分隔、约 1.5 万行）是早期待译导出清单，不是译文** — 第 3 列是日文原文，不要当译文回填。
7. **行号 `line` 是游戏脚本行号，与 jsonl 物理行一一对应**（已验证 0 错位），`fill_cn.py` 依赖 `lines[l-1]`，不要重排 jsonl。
